# Goal · M1 + M2：durable ledger → `nulya session *` → 脚本 extension

> 这是一份**执行契约**，不是设计文档。设计在 [PLAN.md](../PLAN.md) §0、§1（M1/M2）、§3.1–§3.4；现状在 [DESIGN.md](../DESIGN.md)；地图和 physics 在 [CLAUDE.md](../../CLAUDE.md)。
> **每次 compaction 后先重读本文件**，尤其是 §6 进度区。

## 0. 目标（一句话）

让 Nulya 的会话落到磁盘、能被任何进程 attach 和续跑，并让 extension 的制造不再依赖编译——做到 PLAN §1 "M1 → M2 分水岭"：之后 subagent / driver / evolution 全部可以是脚本。

## 1. 范围

**做（按顺序，每步测试全绿再进下一步）：**

1. **M1 durable ledger**（PLAN §3.1）：JSONL 文件 + header + `seq`；`Ledger.create/open/append`；`AgentSession` 从文件恢复；`completeInterruptedToolBatch` 对磁盘残尾生效；`session.prepareStep` 每步扫盘对账 → 改为 CLI 直接 append `capability_note`；`prompt.currentGeneration()` 删除（generation == 文件）。

## 3. 已定决策（不要重开；如认为错了，写进 §6 BLOCKED 并停下，不要自行改方向）

- ledger 文件：`.nulya/sessions/<session-id>.jsonl`；第一行 `{"kind":"header","v":1,…}` 含冻结的 composition（tools/skills/system_prompts/pinned 版本）与 `parent?{session,seq}`；之后每行 `{"seq":n,"kind":…}`。**一个文件 = 一个 generation = 一个 cache scope**；`--parent` 就是 fork / compaction 的机制（compaction 本身不在本 goal 内）。
- Event alphabet **可加不可改**：现有四种保留原字段；`seq` 是 envelope 字段。
- ledger append-only 语义、cancellation 语义、batch 形状（一条 assistant-with-calls ↔ 一条 tool_results）不变——它们在 DESIGN §15.1 冻结面。
- `nulya session *` 是**唯一**的 session 驱动面；不存在 `setTools / setSystemPrompt / setModel / replaceHistory / mutateComposition` 这类动词。想换 composition = `session new`。
- `--max-steps`（及若实现的 `--budget-tokens`）由 kernel 在 `AgentSession` 层强制，不是 CLI 层的循环计数。
- 脚本 extension 与编译 extension **共用** seal / integrity / store / activate / rollback / usage 路径；区别只在 build 阶段"是否编译"和 hash 是否含 compiler_identity。
- usage journal 保持独立文件、v1 格式不变（不要顺手做 M6 的 `version` 字段）。
- CLI 子进程向 session 文件 append 时读 `NULYA_SESSION` 环境变量定位；没有它就沿用现有行为（不写 note）。
- 不加第三个 builtin tool；不在 session 中途改 `tools[]`；不给 tool ledger。

## 6. 进度区（由执行者维护；compaction 后先看这里）

### 关键设计决策（已定，记录理由，稍后进 DESIGN §3）

- **并发 append：单写者 + inbox 目录。** session JSONL 文件只有一个写者（拥有它的
  session 进程）。跨进程事件（CLI 在 `NULYA_SESSION` 存在时产生的 capability_note）
  写进兄弟目录 `<id>.inbox/`（一事件一文件，文件名 `note-<id>-<version>.json` 唯一），
  由 session 在 **step 边界**（`prepareStep`，补齐残尾之后、下一次 model 调用之前）
  排干进主文件。Windows 上无需文件锁；且 batch 不变量成立——note 只落在完整
  tool_results 之后、下一条 assistant 之前，绝不插进 batch 中间。
- **`NULYA_SESSION` = session ledger 文件的绝对路径。** inbox = 同目录下 `<stem>.inbox`。
- **generation == 文件。** `prompt.currentGeneration()` 删除；`Request.generation` 处直接传 0。
- **composition 冻结进 header。** header 存 `{active:[{id,version}], native_tools:[stable-id], max_tools}`。
  resume 时用 header 重建 composition（读那些冻结版本，把 native_tools 当 pin），
  绝不重扫 `current`、绝不重排 usage journal——这样 `session step` 的每个进程都重建
  出**同一** composition，`activate` 也移不动它（physics #2）。
- **内存 `Ledger` 保留**（`init`）给既有测试；durable 是可选后端（`create`/`open`）。最小 diff。
