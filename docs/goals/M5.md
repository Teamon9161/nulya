## 0. 目标（一句话）

给慢速回路（PLAN §3.7）铺好它需要的全部 substrate——**session 的 ground truth（outcome）与 cost（per-step usage）落成 durable facts、extension 能装在用户级目录、一个 built 版本能只进某一场 session 的 composition**——然后用这些 substrate 把**第一个 evolution extension**做成一个普通的 data extension、真实跑一次。内核不认识 "evolution" 这个词。

## 1. 范围

**做（按顺序，每步测试全绿再进下一步；每个子项一个 commit `M5x: …`）：**

1. **M5a · outcome journal。** `src/outcome.zig`（镜像 `tool_stats.zig`）：`.nulya/session-outcomes.jsonl`，行 `{"v":1,"session":"s-…","verdict":"success|partial|failure","note":"…"?,"at":"<RFC3339 UTC>"}`；`Verdict` enum、`append` / `readAll`、crash-tail 修复、未知字段忽略。CLI `nulya session outcome <id> <verdict> [--note <text>]`：校验 id 形状与 session 文件存在（同 `append`）、verdict 合法；**不碰 session 文件、不拿 `<id>.lock`**（正在 `step` 的 session 也能评）；同一 session 可多行。
2. **M5b · per-step usage 落 ledger。** `ledger.Event.assistant` 加可选 `usage: ?Usage{input_tokens, output_tokens, cache_read_tokens, cache_write_tokens}`；`loop.zig` 从 `ModelTurn.usage` 写入；**`prompt.zig` 不投影**（与 `reasoning` 同地位：本轮的 fact，不是模型可见文本）；wire 只在非空写 `usage` 对象，老行读回 `null`；`session events` / `--stream` 的 ledger 行自然带上。
3. **M5c · 多个 extension store root。** 搜索顺序 ① workspace `.nulya/extensions/` ② user `<config.userHome()>/extensions/`（= `~/.nulya/extensions/`，`NULYA_HOME` 整体搬走）③ `extensions.paths`（**只认 trusted 层**；`mergeProject` 现放行的那一行改为忽略）。同 id 在多个 root → **首个 root 胜**（workspace 遮蔽 user）；frozen 版本（`initFrozen`、`skill load` pinned ref、`ext run` 的 entry）按 root 顺序找 `<id>/versions/<v>`——内容寻址，哪个 root 的副本都是同一字节，integrity 照验。**header 不记 root**（`active` 仍是 `{id, version}`）。写端：`ext init [--user] <id>`（draft 建在对应 root）；`ext build <path> [--user]`（落点见 M5d）；`activate | rollback | deactivate <id> … [--user]`（默认作用于持有该 id 的首个 root）；`ext list` 显示 root 列并标出被遮蔽者。改动面：`session.Options.extension_root` → `extension_roots`、`composition.init/initFrozen`、`promotion`、`cli.zig` 各处、`extension/{notes,skills}.zig`。
4. **M5d · `ext build <path>` 按 manifest id 落 store。** 版本目录 = `<store root>/<manifest.id>/versions/<v>`，不再是 `<path>/versions/<v>`。落点：源路径在某个 store root 之内 → 该 root；否则 workspace root；`--user` 强制 user root。对 store 内 draft 字节等价（`ext init` 流程不变）；对 store 外 draft 从"建出 activate 找不到的孤儿 versions/"变成正确行为——是 fix，不是新语义。draft 因此可以在任意路径（仓库里 git 管着的 `extensions/…`、`modes/…`）。
5. **M5e · `session new --with <id>[@<version>]`（可重复）。** 把一个 **built** 版本 union 进本场的 `resolved`（同 id 覆盖 `current`；无 `@version` → 该 id 的 `current`，没有则 exit 1；版本目录不存在 → exit 1）；tools / skills / system_prompts 一起进 composition；header `active` 自然记住，**`initFrozen` 零改动**。这是 composition membership，**不是** native pin（`--pin` 留 M2c）；fork（`--parent`）不继承，driver 自己重传。
6. **M5f · `nulya session list [--json]`。** `.nulya/sessions/` 的只读投影，按 `created` 倒序：`{sessions:[{id, created, parent, model, provider, model_id, events, composition:{active:["id@version"], native_tools}, usage:{input,output,cache_read,cache_write}（assistant.usage 求和）, first_user_text（截断）, outcome:{verdict,note,at}|null（journal 里该 id 最新一条）}]}`；无 `--json` 一行一场。定位同 `config show`：外壳投影，供 evolution skill 与 TUI `/sessions`。

   nulya session append $id "Run one evolution pass now."

## 3. 已定决策（不要重开；如认为错了，写进 §6 BLOCKED 并停下，不要自行改方向）

- **outcome 是 journal，不是 ledger 事件。** 三条理由：session 尾往往没有下一个 step 来排干 inbox；它是 policy 的证据、不是对话（DESIGN §3.3 usage journal 的同一原则）；不给 `prompt.zig` 开"存了但不投影的事件种类"。verdict 三值 `success | partial | failure`；**没有行 = unknown ≠ failure**；不加 `source`（M5 只有人经 CLI/TUI 写；将来 driver 自动记时再加，届时"无 `source` 的 v1 行 = 人评"）。
- **per-step usage 是 `assistant` 事件的不投影字段**（与 `reasoning` 同地位）。provider 阶段被取消的 step 没有 assistant 事件可挂，其 usage 不落盘——诚实接受，不为它造新事件。
- **外壳里不出现任何具体 skill / extension 的名字。** 没有 `nulya session evolution`；evolution 无特权，走与任何 data extension 相同的 build / `--with` / rollback 路径，自己也坐 §3.7.4 的被告席。
- **多 root：workspace → user → `extensions.paths`（trusted 层）；project 层不能加 root**（一个 checkout 不该能决定机器上哪些目录的 `current` 生效——DESIGN §9.5 "只能收窄"的同一不变量）。同 id 首个 root 胜；frozen 版本按 root 顺序找（内容寻址故等价）；**header 不记 root**。
- **`ext build` 的版本落点由 manifest id + store root 决定，不由 draft 路径决定。** draft 位置自由。
- **`--with` 是 composition membership，不是 native pin。** 两根轴分开：`--with` 让 extension 进这一场（tools 变得可 native、skills 进 catalog、system_prompts 进 system blocks）；tool 是否强制占 native 槽仍是 `registry.pinned_native_tools` / 将来的 `--pin`。fork 不继承 `--with`。
- **mode = 贡献 system_prompt 的 data extension + `--with`。** 同一个包两种投放：`activate` = 常驻（每场都有）；不 activate 只 `--with` = 按场。不为 mode 造别的机制。
- **evolution 内容硬规则**（§7）：null result 是一等输出；无 ≥3 场 session 证据不提案；一轮 ≤ 2 条提案；每条提案带 falsifier；报告是跨次记忆——先读上一份、把 unused 提案 `ext deactivate`；只动最小形态（notes / skill 条目 > 脚本 tool），**不 promote、不 pin、不碰 `.nulya/sessions/`、journals、`src/`**。
- 不加第三个 builtin；不在 session 中途改 `tools[]`；不给 tool ledger；ledger 事件字母表可加不可改；usage journal v1 不动。

### 关键设计决策（实施中新定的，稍后进 DESIGN）

- **`src/journal.zig` 只抽 IO**（`appendLine` + `readAll` + crash-tail 修复），schema 各自留在 `tool_stats.zig` / `outcome.zig`。第二个 consumer 出现了才抽，且不抽 `Journal<T>`。
- **`ledger.Usage` 是 ledger 自己的结构**（不 import `provider.zig`，避免 `provider → prompt → ledger` 的环）；`loop.zig` 把 `ModelTurn.usage` 转过来，**四个字段全零 → 不落 `usage` 字段**（老行形状逐字节不变，round-trip 精确）。
- **`ext build` 的落点由新参数 `dest_root: std.Io.Dir` 表达**，版本目录 `<manifest.id>/versions/<v>` 全部相对该 root；编译进程的 cwd 也设为 dest_root（frozen source 与 `-femit-bin` 都在版本目录内），这样 user root 是绝对路径时无需给 `std.Io.Dir` 传绝对 sub_path。
- **root 的 flag 名是 `--user`**（对上 `~/.nulya`，与 `NULYA_HOME` 同一处）。
- **重复 `--with` 同一 id：后者胜**（与 `--with` 覆盖 `current` 的语义一致，不额外造错误）。
- **`session new` 开始写 header `created`**（RFC3339 UTC）：`session list` 按它倒序；老 header 的空 `created` 退化为按 id（本身时间有序）排。

## 7. evolution 内容契约（M5g；写 `prompts/evolution.md` 与 `skills/evolution/SKILL.md` 时照此）

**身份（system prompt 开头）：** 你是慢速回路。你不做任务，你审视做过的任务：什么反复发生、什么贵、什么常失败、什么造了没人用。你的最有价值的输出常常是"别造"。空的提案列表是合法结果；编造提案是失败。你只读 evidence、只写报告和最小形态的沉淀；你不改内核、不动 session 文件、不动 journals、不 promote、不 pin。

**读什么（都经 shell，只读；用聚合管道，不 `cat` 整个 ledger——输出过 emit 预算会被截断落盘）：**
- `nulya session list --json`（每场：composition / parent / 事件数 / usage / 最新 verdict）
- `.nulya/sessions/<id>.jsonl`：`assistant.calls[].args` 里的 shell 命令形状；`tool_results ok=false`；`capability_note`
- `.nulya/tool-usage.jsonl`、`.nulya/session-outcomes.jsonl`
- `nulya ext list`（哪些 extension 有版本、哪些 `current`、被遮蔽的）
- **`.nulya/evolution/*.md`：自己上次的报告 = 跨次记忆，先读它**

**流程：**
0. 上一份报告里的每条提案现在什么状态？被造出来但 usage 为零 → `unused`，`nulya ext deactivate`；被采用 → 记一笔；被证伪 → 记原因。
1. 划证据窗口：上次报告之后的 session；有 verdict 的优先；`failure` 的逐个看。
2. 三问：**什么反复出现**（跨 ≥3 场 session 的同形 shell 命令 / 同类 edit）· **什么常失败**（`ok=false` 聚类、`failure` verdict 的共性、被 `skill load` 过而结局 `failure` 的 skill）· **什么造了没人用**（有 versions、usage 为零的 extension；catalog 里从未被 load 的 skill）。
3. 每个候选二选一：**null result**（必须写"什么证据会改变这个判断"）或**提案**（kind ∈ notes/skill 条目 > 脚本 tool > tool v2 > driver；引用 session id；选最小形态；写 falsifier："若接下来 N 场无调用 / outcome 无改善则 retire"）。
4. 只动最小形态：`edit` 一个 notes / skill 文件、`nulya ext init --script` 出 draft、可 `ext build`（activate 与否写清理由）。
5. 写 `.nulya/evolution/<YYYYMMDD-HHMM>-<session>.md`，固定五节：`## Window` · `## Prior proposals` · `## Null results` · `## Proposals` · `## Nothing else found`；结束本轮，最后一条 assistant 文本是 ≤ 5 行摘要。

**硬规则：** 一轮 ≤ 2 条提案；无 ≥3 场 session 证据不提；null result 与提案同等对待、同等篇幅；报告每节都要在，空节写"none"；不得为满足"有提案"而降低证据门槛。

**SKILL.md（按需 load）放：** 报告模板原文；bash 与 powershell 各一组读证据的配方（列 session、取 header、数事件、聚合 shell 命令形状、join outcome）；`ext init --script` 的最小骨架示例；上面流程的 checklist 版。
